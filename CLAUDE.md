# techlogist1/techlogist1

This is the GitHub **special profile repository**. Its `README.md` is what renders
at <https://github.com/techlogist1> above the pinned repositories. It is not a
project; the README *is* the product, and `assets/*.svg` are its only images.

The repo had zero commits between 2022-02-10 and 2026-09-07.

---

## The one hard rule

**No third-party image URLs. Ever.**

No shields.io, no github-readme-stats, no capsule-render, no typing-animation
services, no visitor counters, no trophy or streak widgets, no language-breakdown
pie. Every image on this profile is generated by `tools/generate.py` and committed
to `assets/` in this repository.

Two reasons, and the second is the one people forget:

1. Every one of those is a third-party dependency that eventually 404s, and a
   dead image on a profile is worse than no image.
2. Several of them render *small numbers* — stars, forks, followers. Putting a
   4 next to a 789,305 draws the eye straight to the weakest figure on the page.
   This profile advertises artifacts, not metrics. `tools/verify.py` enforces the
   URL half of this rule; the numbers half is a judgement you have to keep making.

`tools/verify.py` fails the build on any external `href`/`src`, any `http(s)://`
that isn't the SVG namespace, any `@font-face`, and any `url(http...)`.

## Aesthetic direction

**Warm phosphor.** A CRT terminal photographed on film in 1997 — not green-on-black
hacker cliché, not cold modern grey. Amber, ochre and cream on a warm near-black,
with a single oxblood accent. Monospace throughout, ASCII box-drawing for
structure. Vintage and warm.

Light mode is not an inversion — it is the same instrument printed on aged paper.

## SVG constraints — all of these were found the hard way

The README references SVGs with `<img>`. In that context the browser runs them in
**secure static mode**: no JavaScript executes and no external subresource loads.
Everything below follows from that, or from rasterising and looking at the result.

1. **No JavaScript.** It will not run. Animation is CSS keyframes or SMIL only.

2. **CSS keyframes, never SMIL.** SMIL animations cannot be switched off by
   `prefers-reduced-motion`. Choosing SMIL makes the accessibility requirement
   unsatisfiable, so it is not a free choice between two equal options.

3. **Never CSS custom properties.** resvg — and any non-browser renderer — drops
   `var()` entirely and falls back to **black**. The first hero render was a
   black rectangle on a black background. Write literal colours in the base rules
   and override them inside `@media (prefers-color-scheme: light)`. The degraded
   state has to be the design, not an error state. `verify.py` fails on `var(--`.

4. **`xml:space="preserve"` is mandatory on the root.** The CSS `white-space:pre`
   property is honoured by browsers but *not* by resvg's text layout. Without the
   attribute every run of padding spaces collapses to one, and the ASCII frames
   stop closing. This is the single most load-bearing attribute in these files.

5. **Never mix a string-rendered run with a separately-positioned element in the
   same row.** The string uses the *viewer's* actual monospace advance; the
   positioned element uses the `CH` constant in `generate.py`. Consolas is 0.55em,
   DejaVu Sans Mono and SF Mono are 0.60em — so a hardcoded constant is wrong on
   somebody's machine no matter what value it holds. Every row goes through
   `line()`, which emits one `<text>` with `textLength` pinning it to the grid.

6. **`textLength` padding must live inside a styled `<tspan>`.** Emitted as a bare
   unstyled run, resvg loses it and the row's closing rule collapses back against
   the content. Measured with a pixel diff, not guessed — `line()` folds padding
   into the second-to-last cell for exactly this reason.

7. **Line advance ~1.18em.** At `LH: 24` against a 17px font every vertical
   box-drawing rule was visibly broken between rows. Box-drawing glyphs tile at
   roughly the line spacing a terminal uses; `LH = 20` at 17px, `LH = 16` at 13px.

8. **Fonts: generic monospace stack only.** A webfont referenced by URL fails
   silently and breaks the layout for every visitor. Nothing is embedded, so no
   file pays for a font.

9. **Base CSS state must be the *finished* frame.** Keyframes supply only the
   entrance, via `animation-fill-mode: backwards`. A renderer with no animation
   support then shows a complete image rather than a blank one — and
   `prefers-reduced-motion: reduce` becomes a one-line `animation: none`.

10. **Budget: 150 KB per file, 400 KB for the whole README.** Currently ~35 KB
    total across six files, so there is a lot of headroom. `verify.py` enforces both.

### Verifying a change

```
python tools/verify.py "assets/*.svg"     # static constraints, no deps, runs in CI
python tools/check.py assets/hero.svg        # rasterises both palettes with resvg
```

`resvg` honours neither `@media` nor `@keyframes`, which is exactly what makes it
useful: it shows the *base* state. To see the light branch, `check.py` appends the
light rules to the end of the style block so they win on source order. **Look at
the PNGs.** Every real defect in this repo was found by looking, not by reasoning.

## Animation discipline

The failure mode is a page where five things loop at once and the whole thing
reads as a slot machine.

- **At most two elements animate continuously.** Currently exactly two: the
  hero's scanline drift, and the commit ticker's horizontal roll. Adding a third
  means removing one.
- Everything else animates **once on load and settles**, or is static. The
  activity graph wipes in left-to-right once. The stats, releases and chain panels
  do not animate at all — they are dense with text, and motion made them harder
  to read rather than more alive.
- Every animated file needs its own `prefers-reduced-motion` block.

## How the workflow works

`.github/workflows/profile.yml`, daily at 04:17 UTC plus `workflow_dispatch`, plus
a push trigger when the generator itself changes.

**One workflow regenerates every panel and commits once.** Not one per widget:
four workflows would be four independent failure surfaces and four ways for the
profile to end up partially stale with nothing on the page saying so.

The degradation path, which is the point of the design:

- A generator that raises **leaves its existing SVG untouched**. The last good
  image stays committed and the README never shows a broken image.
- A data source that comes back empty produces a **legible "no data" frame**, not
  an empty file. An empty file in an `<img>` is a broken-image icon, which is
  worse on the page than stale data.
- Writes are **atomic** — temp file, validated, then `os.replace` — so a crash
  mid-write cannot leave a truncated SVG behind.
- The generator step is `continue-on-error: true` **on purpose**. Failing the job
  there would skip the commit and throw away the panels that *did* regenerate.
  The failure is re-raised in a final step instead, so the run still goes **red in
  the Actions tab**. Failure is never silent.

**Panels are deterministic given the same upstream data** — no generated-at
timestamps anywhere. If they carried one, the workflow would commit on every run
whether anything changed or not, and those commits would then inflate the very
activity graph this script draws.

**Token.** The workflow uses `secrets.PROFILE_TOKEN` if present and falls back to
`secrets.GITHUB_TOKEN`. See "Contribution counts depend on the token" below —
this matters more than it looks.

**Caveat:** GitHub disables scheduled workflows after 60 days with no repository
activity. The workflow's own commits count, but if the data never changes for 60
days there are no commits and it can be switched off. Re-enable from the Actions tab.

## The panels

| file | what it is | data source | animates |
|---|---|---|---|
| `hero.svg` | hand-built CRT frame, name and three projects | none, static content | scanline drift (continuous) + entrance |
| `activity.svg` | contribution year as an ASCII density graph | GraphQL `contributionCalendar` | wipes in once |
| `stats.svg` | real counts, no stars/forks/followers | REST `stats/contributors`, `languages`, `releases` | no |
| `releases.svg` | latest release or tag per repo | REST `releases`, `tags` | no |
| `chain.svg` | recent commits as a verified hash chain | REST `commits` incl. parents | no |
| `ticker.svg` | recent commit subjects, scrolling | REST `commits` | horizontal roll (continuous) |

`chain.svg` is the one that isn't a standard profile widget. Git is already a
digest-chained provenance store — every commit names its parent's hash — which is
structurally the thing ulpf builds for logs. The generator walks the real chain and
**actually verifies** each link rather than illustrating one, and prints the count
of links checked and broken.

### Contribution counts depend on the token

`contributionsCollection` returns different numbers depending on who is asking.
Queried with the account owner's PAT it includes commits to private repositories;
queried with a repo-scoped `GITHUB_TOKEN` it sees public contributions only. The
number on the panel will therefore *drop* if the workflow falls back to
`GITHUB_TOKEN`. If that matters, add a fine-grained PAT with read access to the
account's repositories as the `PROFILE_TOKEN` secret. `stats.svg` labels its
repo-derived rows "public repositories" precisely so the smaller figure is still
an honest one.

## Repository facts worth not re-deriving

- Pinned, deliberately, exactly three: `flint`, `vysted-terminal`, `ulpf`. GitHub
  permits fewer than six and three that survive scrutiny beat six with padding.
- `luminfaber` and `study-tracker` were made **private** on 2026-09-07 — a scaffold
  with no README and an empty repo respectively. Deleting `study-tracker` would
  have needed the `delete_repo` scope, which `repo` does not include.
- `ulpf` had no `LICENSE` file despite `Cargo.toml` declaring MIT, so it was
  legally all-rights-reserved while carrying an outside fork. Fixed 2026-09-07.
- `ulpf v0.1.0-rc3` was published the same day; all three drafts had **empty**
  release bodies.
- Account metadata (bio, blog, location, socials) is set through `PATCH /user`,
  which needs the **`user`** OAuth scope. `repo` is not enough:
  `gh auth refresh -h github.com -s user`.
